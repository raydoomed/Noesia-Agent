# 接入一个新的消息平台

这份说明写给要在 Noesia 里加消息平台（飞书、企微、QQ、微信之类）的人。仓库里已经内置了
`feishu`、`qqbot`、`wecom`、`weixin` 四个，可以照它们的结构抄。

两条路，选一条：

- **插件路（推荐）**：不改内核，把平台做成一个插件目录放到数据根下，重启网关即可生效。
- **内置路**：直接把适配器写进内核（只有我们自己在维护内核时才用）。

---

## 一、插件路（推荐）

### 目录放在哪

- 内置插件：`src/engine/plugins/platforms/<平台名>/`
- 用户插件：`<数据根>/plugins/platforms/<平台名>/`（本机就是 `data/NoesiaHome/plugins/platforms/…`）

一个平台一个目录，目录名就是平台名。目录里至少一个声明模块 `<平台名>.py`，只依赖内核公开接口，
不 import 私有实现。

### 声明模块要给出什么

1. 平台的内部名与显示名（下拉菜单、状态栏里用）
2. 适配器类（方法清单见下节）
3. 需要哪几项凭证（app_id / secret / token 之类），从 `<数据根>/.env` 的哪个变量读
4. 默认开着还是关着

### 生效方式

改完 `<数据根>/config.yaml` 里这个平台的开关，重启网关。热加载只在改过插件代码又调了
`reload_gateway_plugins()` 时发生；配置项本身的变化不会自动重载。

---

## 二、内置路（维护内核时才用）

新增一个平台要动 16 处，缺一处就会出现「日志里有、界面上没有」这类怪现象。按顺序改完再跑测试。

### 1. 适配器 `gateway/platforms/<platform>.py`

继承 `gateway/platforms/base.py` 的基类。必须实现：

- 连接与断开（长连接还是轮询，由平台 SDK 决定）
- 收到消息 → 统一成内核的消息结构（发送者、频道、文本、附件、回复锚点）
- 发送消息，并回报「成功与否 + 平台侧消息 id」
- 平台能力探测（能不能编辑、能不能加按钮、能不能撤回）

基类里有默认桩的可以按需覆盖：编辑、撤回、表情回执、已读、正在输入、按钮交互。

平台支持可点按钮时，按钮点击也转成入站消息，不要另开一条事件通道。

### 2. 平台枚举 `gateway/config.py`

枚举加一项；同时在 `platforms_dir` 那套发现逻辑里登记目录名，否则打包后的插件不会被扫到。

### 3. 适配器工厂 `gateway/run.py`

这里决定凭证从哪读、缺凭证时是「静默关着」还是「状态栏提示未配置」。
**我们的约定：缺凭证不报错，只标成未配置。**

### 4. 授权表 `gateway/pairing.py`、`gateway/authz_mixin.py`

谁能跟这个平台上的会话说话：白名单、配对码、群聊里是否只响应 @。不登记就等于谁都能驱动她。

### 5. 会话来源 `gateway/session.py`

入站消息要算得出稳定的会话键（平台 + 频道 + 线程），否则同一段对话会被拆成许多会话，
记忆与上下文全断。

### 6. 平台提示 `platform_hint`

告诉模型「这是哪个平台、回复有什么限制」（字数、能不能发文件、能不能加按钮）。写在平台配置里，
不要塞进通用系统提示。

### 7. 工具集 `toolsets.py`

这个平台能用哪些工具。私聊可以全开；群聊通常要收窄，发消息、定时这类单独授权。

### 8. 定时投递 `cron/scheduler.py`

定时任务的产出往哪投。没登记的平台在定时任务里选不到，跑到点也没地方送。

### 9. 发送消息工具 `tools/send_message_tool.py`

让她能主动发消息到某个会话。这里要按平台校验目标存在、她有没有权限。

### 10. 定时任务工具 `tools/cronjob_tools.py`

定时任务 schema 里的投递目标枚举要包含这个平台。

### 11. 频道目录 `gateway/channel_directory.py`

把平台上的会话列出来给人挑（选投递目标时用）。没有它，用户只能手打会话 id。

### 12. 状态显示 `noesia_cli/status.py`

`noesia status` 里的那一行：连上没有、最后一条消息多久前、凭证从哪读的。**不要把凭证打出来。**

### 13. 配置向导 `noesia_cli/gateway.py`

`noesia setup` 里这几步：填凭证、选默认会话、试发一条确认能通。

### 14. 脱敏 `agent/redact.py`

平台返回的手机号、openid、群 id 在写日志或写记忆前要脱敏，规则加到这张表里。

### 15. 文档

`docs/` 里加一页（怎么配、要哪些权限、常见错误），能力矩阵补一行（能发图吗、能加按钮吗、能撤回吗）。

### 16. 测试 `tests/gateway/test_<platform>.py`

至少覆盖：入站消息映射、会话键计算、授权拒绝、发送失败的处理、缺凭证时不崩。

## 三、改完怎么核

```bash
# 1. 全量测试
./.venv/Scripts/python.exe -m pytest -q

# 2. 只跑网关相关的
./.venv/Scripts/python.exe -m pytest tests/gateway -q

# 3. 把平台名全局搜一遍：别的平台都出现、唯独新平台没出现的地方，就是漏的那一处
grep -rn "feishu\|wecom\|qqbot\|weixin" src/engine --include="*.py" | head -30
```

## 四、几条约定

- 缺凭证一律「降级为未配置」，不抛异常、不阻断启动
- 平台差异只写在适配器和 `platform_hint` 里，不往通用对话循环里塞 if
- 日志里出现的一切 id 都过 `agent/redact.py`
- 入站消息先落库再处理，进程被中断也不丢消息
